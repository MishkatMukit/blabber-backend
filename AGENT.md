# AGENT.md — Blabber Backend Coding Rules

This file defines the **core rules of coding** for this repository. Any agent or developer working here MUST follow these rules. When in doubt, ask — or default to the conventions below.

## Architecture

**Route → Controller → Service (RCS)** pattern. Requests flow through exactly one path:

```
Route (middleware chain) → Controller → Service → Prisma → PostgreSQL
```

- **Routes** define the URL + middleware chain (`auth`, `validateRequest`) and delegate to a controller.
- **Controllers** handle HTTP concerns only: call the service, build the response with `sendResponse()`. No business logic, no DB queries.
- **Services** contain ALL business logic and database access via the Prisma singleton. No `req`/`res` here — operate on plain payloads and return data.

Every feature lives in `src/modules/<feature>/` as three files: `<feature>.route.ts`, `<feature>.controller.ts`, `<feature>.services.ts`. New features COPY the `src/modules/example` pattern.

## Non-Negotiable Rules

1. **No `try/catch` in controllers.** Async errors are forwarded by `catchAsync()`. Wrap every controller handler: `const getAll = catchAsync(async (req, res) => { ... })`.
2. **Every response goes through `sendResponse()`** — uniform shape: `{ success, statusCode, message, data, meta }`. Never `res.json()` raw objects in controllers.
3. **All request bodies are validated by Zod** via the `validateRequest(schema)` middleware. Schemas live in `src/validations/requestSchemas.ts`. Never trust raw `req.body` in a controller.
4. **Services throw plain `Error("message")`** — never return error objects. The `globalErrorHandler` maps errors to proper status codes.
5. **No business logic or DB access in routes or controllers.** Only services touch Prisma.
6. **Auth-protected routes use the curried `auth(...)` middleware.** `auth()` = any authenticated user. `auth(Role.ADMIN)` = role-restricted. Access the logged-in user via `req.user`.
7. **Never log or return passwords.** When fetching users, always `omit: { password: true }`.
8. **Never modify generated code.** `generated/prisma/` and `dist/` are build output — regenerate, don't hand-edit.

## Error Handling

- `globalErrorHandler` maps Prisma errors automatically:
  - `P2002` (duplicate) → **400**
  - `P2003` (FK constraint) → **400**
  - `P2025` (record not found) → **404**
  - Validation/init/connection errors → friendly messages with correct codes
- **Use `findUniqueOrThrow()`** for single-record lookups that must exist — it triggers `P2025`, which becomes a clean 404. Don't hand-check for `null` and throw your own 500.
- Route not found falls through to `routeHandler` (404 JSON with the original path).

## Database & Prisma

- **Split Prisma schema** under `prisma/schema/`: one `.prisma` file per model, `enums.prisma` for all enums, `schema.prisma` for generator + datasource only.
- **PostgreSQL via `@prisma/adapter-pg`** — the client is created once in `src/lib/prisma.ts` and imported everywhere. Never create a second `PrismaClient`.
- **UUID string primary keys**: `id String @id @default(uuid())`.
- **Snake_case table names** via `@@map()`.
- Schema changes: edit the model file, then `npx prisma migrate dev --name <migration_name>`. The generated client (in `generated/prisma/`, gitignored) is regenerated by `npm run build` — run `npx prisma generate` after cloning and after schema edits.
- **Multi-table writes MUST use `prisma.$transaction()`** — never a sequence of separate awaits that can partially fail.
- Pagination convention: `{ page, limit, total }` in `meta`, with `skip = (page - 1) * limit` and sensible defaults.
- Dynamic filters: build an `AND` array, push conditions only when present, pass to `where`.

## Auth & Tokens

- **JWT dual-token**: access token (`1d`) + refresh token (`7d`), signed with separate secrets from env.
- Tokens travel in **httpOnly cookies** (`accessToken`), with `Authorization: Bearer <token>` as fallback.
- Sign with `jwtUtils.createToken(payload, secret, expiresIn)`; verify with `jwtUtils.verifyToken` (check `.success` first).
- Passwords hashed with **bcryptjs** using `BCRYPT_SALT_ROUNDS` (default 10) — never store plaintext.

## Configuration

- **All env vars read through `src/config/index.ts`** — never call `process.env` directly elsewhere. Add new vars there and to `.env`/`.env.example`.
- CORS is locked to `APP_URL` with `credentials: true`. The frontend origin must be set there.
- Never commit `.env`. Secrets live in `.env.example` as empty placeholders only.

## Validation

- All Zod schemas in `src/validations/requestSchemas.ts` — one file, named exports.
- Use `z.email()` for emails, `min()` with human-readable messages, `.trim()` on strings.
- Reference Prisma enums in schemas via `z.enum(Role)` importing from `generated/prisma/enums`.
- After validation, `req.body` is replaced with the parsed/typed result — controllers get clean data.

## Response Shape

Success responses (via `sendResponse`):

```json
{ "success": true, "statusCode": 200, "message": "...", "data": { }, "meta": { "page": 1, "limit": 10, "total": 42 } }
```

Errors (via `globalErrorHandler`):

```json
{ "success": false, "statusCode": 500, "name": "...", "message": "...", "errorDetails": "stack..." }
```

## TypeScript Style

- Strict mode, `verbatimModuleSyntax` — **use `import type` for all type-only imports**.
- `noUncheckedIndexedAccess` — index access can be `undefined`; narrow it.
- Naming: `sendResponse`, `catchAsync`, `jwtUtils` are exported consts; controllers/services exported as `{ getAll }` / `{ getAllFromDB }` objects.
- Use the `req.user` augmentation from `src/Interfaces/user.interface.ts` — never cast `req` to any type manually.

## Workflow

```bash
npm run dev        # development (hot reload)
npm run build      # prisma generate + tsup bundle
npm start          # run production build
npx prisma studio  # browse the database
```

- Always run `npm run build` (or at least `npx prisma generate`) after changing the Prisma schema before running the server.
- Keep modules small and single-purpose. If a service grows past ~100 lines of one concern, split it.
